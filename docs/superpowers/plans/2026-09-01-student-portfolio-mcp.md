# Student Portfolio Website MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a guarded npm stdio MCP server that lets Pi, DeepSeek Harness, Codex, and Claude Code inspect, edit, test, commit, push, and verify student portfolio websites.

**Architecture:** A thin MCP registration layer in `src/index.js` exposes six tools backed by deterministic operations in `src/workflow.js`. Mutations use preview/execute approval tokens bound to a fresh Git snapshot; the host model generates patches, while the server enforces paths, commands, Git scope, and release boundaries.

**Tech Stack:** Node.js 18+, ESM JavaScript, `@modelcontextprotocol/sdk` 1.30.0, Zod 4.5.4, Node built-in test runner, Git CLI, optional GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-09-01-student-portfolio-mcp-design.md`

## Global Constraints

- Package name: `student-portfolio-website-mcp`; initial npm version: `1.0.0`; license: MIT.
- Runtime: Node.js 18 or newer; local stdio transport only.
- Six tools only: `inspect_project`, `apply_patch`, `run_checks`, `commit_changes`, `push_changes`, `verify_github_pages`.
- No embedded model API, arbitrary shell, force-push, ref deletion, remote mutation, credential management, HTTP transport, telemetry, or updater.
- Mutation confirmations are exactly `WRITE`, `RUN`, `COMMIT`, and `PUSH`.
- Every mutation is preview then execute with a one-time expiring token tied to root, snapshot, operation, and arguments.
- All subprocesses use argument arrays with `shell: false`; Windows npm execution uses `npm.cmd`.
- Preserve unrelated tracked, staged, and untracked work; stage only explicit paths.
- README must document PowerShell, Pi, DeepSeek Harness, Codex, and Claude Code installation.

const pkg = JSON.parse(readFileSync(new URL("../package.json", import.meta.url), "utf8"));

export function createServer(workflow) {
  const server = new McpServer({ name: "student-portfolio-website-mcp", version: pkg.version });
  server.registerTool("inspect_project", {
    description: "Inspect a student portfolio repository and return a safe workflow snapshot.",
    inputSchema: { projectPath: z.string().min(1) }

export function toToolResult(result) {

    content: [{ type: "text", text: result.summary }],
    structuredContent: result,
    isError: result.ok === false
  };
}

- [ ] **Step 3: Implement approval records and path guards**

Keep approval records inside `createWorkflow`:

```js
const approvals = new Map();
const APPROVAL_TTL_MS = 5 * 60 * 1000;

function issueApproval(operation, binding) {
  const token = randomUUIDImpl();
  approvals.set(token, { operation, bindingHash: hashJson(binding), expiresAt: now() + APPROVAL_TTL_MS });
  return token;
}

function consumeApproval(token, operation, binding) {
  const record = approvals.get(token);
  approvals.delete(token);
  if (!record || record.operation !== operation || record.expiresAt < now() || record.bindingHash !== hashJson(binding)) {
    throw new Error("Approval token is invalid, expired, stale, or already used");
  }
}
```
